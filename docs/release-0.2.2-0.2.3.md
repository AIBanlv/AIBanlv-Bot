# 0.2.2 / 0.2.3 在线更新与增量更新验收

0.2.2 修复退出后安装辅助进程未继续运行的问题，并修正 Windows 任务栏品牌关联。
0.2.3 使用相同功能和运行时，仅提高版本及更新说明，用于验证 0.2.2 的在线更新。
两个版本各有独立发布目录：`demos/web-desktop-pet/dist/releases/0.2.2/` 和 `0.2.3/`。
每个目录只上传 EXE、对应 `.exe.blockmap` 和 `latest.json` 三个文件。

## 第一轮：发布 0.2.2 并保留基线

1. 上传 **0.2.2** 的 EXE 和 blockmap 至七牛云 `desktop-updates/windows/x64/`。
2. 最后用 **0.2.2 目录中的 latest.json** 覆盖线上清单，刷新该 URL 的 CDN 缓存。
3. 在当前旧版中检查更新，确认发现 **0.2.2**，完成应用内下载和校验。
   应用内下载会保存增量基线；即使随后手动安装，该基线也能保留。
4. 旧版本身仍可能存在安装交接问题。若退出后没有安装向导，彻底从托盘退出旧版，
   再运行本次下载的 `%APPDATA%\Control Device\updates\setup.exe`，
   或本地 `dist/releases/0.2.2/AIBanlv-0.2.2-win-x64-Setup.exe`。
   关闭设置窗口只会隐藏窗口，不等于退出；安装报文件占用时退出后点“重试”，不要“忽略”。
5. 安装后打开应用，确认当前版本 **0.2.2**、任务栏显示 AIBanlv 图标。

不要同时先发布 0.2.3 的清单，否则第一轮会直接跳到 0.2.3。
不要清理 `%APPDATA%\Control Device\updates\base.exe`、`base.blockmap`、`base.json`。
仅手动安装不会生成下载基线；如果缺少有效基线，下一轮可能完整下载，属于预期回退。

## 第二轮：验证 0.2.2 → 0.2.3

1. 上传 **0.2.3** 的 EXE 和 blockmap，最后覆盖其 **latest.json**，刷新清单 CDN 缓存。
2. 在已安装的 **0.2.2** 中检查更新，应发现 **0.2.3**。
3. 下载时应显示增量重建，并复用第一轮的基线。磁盘上的完整安装包仍约 704 MiB，
   这是重建结果大小；实际网络传输量才是判断是否增量的依据。
4. 点击“退出并安装”，应退出主程序并打开安装向导。安装完成后确认版本 **0.2.3**，
   账号绑定、设置及任务栏图标正常。

清单检查地址：<https://zhanlvgpt.ieasysell.com/desktop-updates/windows/x64/latest.json>。
沿用现有 CDN 规则：EXE/blockmap 长期缓存，更新目录其余文件不缓存；清单替换后仍刷新旧缓存。
保留旧版本文件，不覆盖版本化 EXE。撤回问题版本可恢复旧清单停止继续分发，
已升级客户端不会自动降级，需要发布更高的修复版本。

## 任务栏修复范围

使用稳定的 `com.zhanlv.aibanlv.desktop` 标识，与旧 Control/Electron 分组及开发实例分离。
安装版窗口的重新启动图标直接指向内嵌 AIBanlv 图标的 EXE。
启动时为已有且指向当前 EXE 的桌面、开始菜单快捷方式同步图标和应用标识。
保留原安装目录、用户资料目录和安装注册表身份，不修改用户手动固定的任务栏项目。
如旧固定项仍留在任务栏，可取消旧固定项，再固定新版正在运行的 AIBanlv。

Windows 要求窗口、进程和快捷方式使用一致的应用标识，详见
[微软 AppUserModelID 文档](https://learn.microsoft.com/en-us/windows/win32/shell/appids)。
