# 鼠标抚摸数字人

## 默认鼠标穿透与动画分离（2026-11-03）

当前设备版默认开启人物区域鼠标穿透。输入卡片、音量/尺寸、麦克风、设置、隐藏、拖动柄与实时记录继续响应鼠标。拖动柄位于输入卡片，不应因人物穿透而禁止移动窗口。

穿透时禁用人物触碰，但继续播放渲染、口型和闲置表情；不再向形象 iframe 发送 `paused: true`。仅隐藏窗口会暂停画面。此规则修正旧代码将“鼠标穿透”等同“暂停动画”造成的卡住现象。本地模式也可完成数字人渲染和对话就绪，不要求线上设备绑定。

## Mac 未聚焦窗口的首次触碰

人物窗口使用 `showInactive()` 显示，避免抢占用户正在操作的应用。
macOS 必须同时设置 `acceptFirstMouse: true`，让未聚焦窗口的第一下点击
也进入人物的触控事件；否则系统默认只激活窗口，会丢失这次轻点或抚摸。
此选项同时适用于 Intel 与 Apple Silicon，其他平台忽略该 Mac 专用选项。
触碰后的合并、冷却、失焦取消、鼠标穿透和原有语音链路保持一致。
安装包需要重新构建才能包含此修复。

## 隐藏触碰消息修订（0.1.4）

手势仍提交到原语音链路，数字人的文本回复、声音和口型正常显示与播放。
普通文字及语音识别的用户气泡保持显示，未发送草稿保留。

## 语音回应修订

用户已要求抚摸后同步语音回应，本节取代下文“不触发云端请求”的早期范围。
完成有效抚摸后等待 550ms，合并连续手势；每 4 秒最多触发一次。
复用当前角色的 Realtime、计费、LAM 和音频时钟，显示简短触碰记录及真实回复，保留文本草稿。
提示在主进程固定生成，不从渲染器接收提示词；只有当前可见、已绑定且形象就绪的数字人可触发。
对话忙、预览动作、鼠标穿透、失焦、取消、角色切换或隐藏时，不排队补发。
无须开启麦克风；收起对话框仍可抚摸并听到回应，重新展开可查看气泡。
键盘互动同样触发回应。单击、静止按住和取消手势不触发。
验证使用现有本地 provider/billing 夹具，不创建正式收费测试会话。

## 目标与已确认交互

用户已确认：按住鼠标在数字人上来回抚摸，数字人以表情、动作回应。
参考旧 Control 的 `android-native/digitalhuman-core/src/main/assets/digitalhuman/touch-interaction.js`
和 `ios-native/keyframeface/AIBANLVTouchInteraction.swift`：相对位移跟随、限幅、阻尼、松开回正。
Windows 使用人物区域作为交互范围；输入卡片左下角的角色名称用于拖动窗口。

## 实现范围与验收条件

- 左键或单指按住移动，头部与视线平滑跟随；移动满 220ms 且路径至少 22px 后提供轻微微笑反馈。
- 松开、取消、失焦、隐藏、角色切换、鼠标穿透或开始对话/动作预览时释放触控，避免覆盖语音口型。
- 角色名称可鼠标拖动，方向键仍可移动窗口；人物按钮支持 Enter/空格进行键盘互动。
- 触控只使用本地渲染，不触发云端请求、不新增依赖、不修改旧 Control。
- 不更改人物尺寸、透明界面、粒子、麦克风及常驻输入卡片行为（卡片不能收起）。

## 结构与代码约定

`electron/device-touch.mjs` 负责手势及平滑表达，`device-pet.mjs` 接入当前渲染消息和优先级。
沿用 ES modules、单引号、camelCase，以及现有 `neutralExpression()`/presentation pose 协议。
例如：`touch.cancel()` 在上下文变化时清理指针及动画。
打包清单和私有 HTTP 路由包含新模块；测试位于 `tests/device-touch.test.mjs`。
