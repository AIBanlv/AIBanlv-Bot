# 桌面端账号登录

> 历史规格：2026-11-02 已按用户要求移除桌面账号登录及自动授权流程。
> 现行功能仅允许扫码，见[扫码登录与迁移](qr-only-desktop-spec.md)。下文仅保留历史决策和验收记录。

状态：用户于 2026-10-22 确认“按此规格实现”，源码实现与合并后验证已完成。

## 目标与验收

在桌面伴侣设置页提供“扫码绑定”和“账号登录”两个可切换入口。
使用者任选一种完成当前电脑的授权，无需先扫码再登录。
账号登录复用旧 `control` 的账号密码接口；登录成功后使用现有控制协议
申请绑定当前安装实例，以服务端 `bind_success` 为授权完成依据。
随后复用现有线上形象、默认上官婉儿和实时对话流程。

- 保留扫码二维码、有效期、刷新和已有绑定恢复行为。
- 登录表单提供账号、密码、提交中和失败提示，支持键盘提交并防止重复请求。
- 密码错误、网络失败、设备已属于其他账号或绑定失败时不得显示授权成功。
- 登录响应须包含有效 token、用户和租户身份；不根据输入账号推断身份。
- 切换入口、断线或关闭程序时，取消客户端登录/授权等待，忽略迟到的登录响应；
  不把取消的尝试改报为登录成功。已发送的绑定请求不能由现有协议撤销，
  设备仍遵循服务端确认的真实绑定状态，详见下方协议边界。
- 不在已有绑定上自动替换账号；账号变更须先通过现有服务端解绑协议。
- 本规格的原始范围不含注册、找回密码或第三方 OAuth。2026-10-23 后续新增
  邮箱注册，范围与验证独立记录在 [邮箱注册规格](account-registration-spec.md)；
  注册后继续复用本规格的登录与绑定流程，找回密码与第三方 OAuth 仍不接入。

## 已核实的现有协议

- 参考 `control/pages/login/account-login.vue` 与 `control/api/request.js`。
- `POST https://scrm.ieasysell.com/new/oauth/token`，沿用现有参数及
  Basic 客户端认证；兼容顶层或 `data` 包装的响应和 `tokenData`。
- 参考 `control/utils/wsControl.js`：控制端 `controller_online`、
  `bind_request`，使用本机服务端签发的有效 `bindToken`。
- 设备端仍以 `device_online` 注册自身，接收正式 `bind_success`；
  不在本地伪造 bound 状态，不把账号 ID 当作设备身份。
- 当前安装 ID 和服务端设备绑定在重启后沿用；密码不持久化。
  登录 token 仅在主进程当前授权期间使用，不写入本机配置。

## 边界

- 始终：使用服务端确认的绑定身份，登录网络请求仅在主进程进行，
  不向渲染器返回 token、密码或包含密码的 URL，限制超时和响应大小。
- 需另行授权：生成 EXE 或安装包、改变后端接口或新增第三方登录。
- 禁止：修改旧 `control` 仓库、覆盖现有实时计费改动、提交私密配置，
  日志输出凭据、通过自动化登录正式账号或消耗正式会话额度。

## 已发送请求的取消边界

现有后端 `ControlChannelHandler` 的 `bind_success` 仅包含设备、用户、
租户身份，不回传 `requestId` 或绑定版本。扫码成功、账号授权成功以及
重新上线恢复绑定使用同样的消息；控制连接关闭不会回滚服务端绑定。
因此取消停止 HTTP 请求、临时控制连接和客户端等待，不自动解绑或
屏蔽真实设备绑定。取消时请求已经发送则提示“已发送的授权以服务端
绑定状态为准”。服务端已完成绑定时仍加载正常形象；取消的登录任务
保持非成功状态。账号变更继续要求通过现有 Control 解绑。
如果需要原子撤销已发送的授权，须另行设计带版本关联的后端协议，
不能仅在客户端屏蔽同身份消息或自动发起补偿解绑。
