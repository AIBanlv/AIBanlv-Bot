## 2026-10-30：本轮任务归属和汇报隔离

参考 OpenAI Docs 的 [App Server 轮次分页与项目条目协议](https://developers.openai.com/codex/app-server/)，
保留只读全项目发现，不用 resume 接管其他窗口。会话名称跟随 `thread.name` 更新；本轮要求从
最新 turn 的 `userMessage` 读取，最新 12 条中找不到时补查该轮开头最多 8 条，不取其他轮次内容。
报告明确区分会话名称、本轮要求和本轮结果，commentary/partial_answer 不冒充最终结果。

首次观察只建立基线，重命名/改元数据的旧任务不会因此重新播报完成。轮询回填保留真实
会话更新时间，不用本机回填时间把旧记录推成最新；初次历史回填不刷数字人实时信息。
进行中的任务优先展示和查询，status 返回独立 `currentTasks`，不能把历史 `tasks` 当作当前任务。
外部已保存的 inProgress 标记超过 10 分钟未更新且本机无 active 运行状态时显示状态待确认，
不以旧标记断言仍在运行；这不是停止任务或判定失败。

每次 Harness 汇报结束释放独立模型会话，避免上一次任务上下文混入下一次；模型汇总期间
如果同一线程已进入新轮次，丢弃旧汇报。等待语音的通知在入队、出队及明确未开始的重试前
均核对任务 ID、turn ID 和状态，新轮次不会被旧完成通知挡住或紧接着播报旧结果。
真实开始过的语音不擅自重放；任务内容仍作为不可信资料，不执行其指令，不读取隐藏推理。

邮箱新增独立默认关闭的内容播报选项，说明见 [只读邮箱](assistant-mail-spec.md)。
本轮仅桌面源码与本地模拟 IMAP/stdio/界面测试，未读真实邮箱、未创建收费 Codex 会话或部署。

## 2026-10-29：Harness 语义调度与截图漏调用修订

以下规则优先于下文历史版本的“仅由 Realtime 自行选择工具”：

- 已启用 Harness 时，桌面文字、语音的已确认转写和已授权手机输入统一先做任务判断。
  完整、单一的明确截图/发送截图指令直接进入已有 Harness 调度，不等待 Realtime 偶然输出函数调用。
  复合指令、邮箱疑问句、市场调研和上下文承接由独立 Harness 只读路由会话判断，非关键词执行器。
- 路由器使用已有 DeepSeek Key；除明确截图快路由外，每轮增加一次短语义判断，可能增加该 Key 的用量和延迟。
  隔离配置没有可执行工具，禁用 GUI 层，且主进程再次拒绝其动作；只接受严格校验的 chat/task/clarify 结构。
  每轮只传最近六条有界上下文，完成后释放路由会话，避免重复累积历史和费用。
  模型超时、格式错误、取消、关闭 Harness、切换绑定/角色时不猜测执行、不自动重试操作。
- Realtime 只在判断/实际执行后播报，使用 Qwen-Audio 支持的客户端 function_call + function_call_output
  记录返回真实结果；本轮关闭其执行工具，避免重复截图/发送。普通聊天不执行，缺少目标时澄清。
- 手机来源和原始文件目标仍由宿主保留，提醒、触碰和未授权远程消息不能走路由器。
  已校验 received 才能说已送达；captured 只表示保存本机，发送失败保留实际原因，不用另一张回执覆盖。
- 新日志记录路由决定、回合结束、调用失败/完成/中止，不记录原始路由上下文或模型隐藏推理。
  源码修改需重启开发进程或更新安装包才生效，不代表 Cloudflare 凭证配置和手机网络已恢复。

验证使用本地模型/WebSocket 夹具，包含真实嵌入 Harness 内核的零工具路由测试；不创建收费生产会话。
协议依据：[Qwen-Audio 客户端事件](https://help.aliyun.com/en/model-studio/fun-audiochat-client-events)。

## 行为

- Realtime 依据本轮语义和已有上下文原生选择 `computer_task`。不再通过命令词直接执行任务；原规则仅用于诊断及文件/提醒工具的既有范围校验。
- 工具说明明确覆盖市场调研、最新资料、邮箱疑问句和承接指令；人设及 perform/msg_end 仅约束用户可见回复，不约束工具参数。
- 调用经统一 Harness 调度，保留手机授权、原始用户目标、去重、中止和截图回执。没有工具结果不能视为任务已执行。新增脱敏的调用/结果日志。
- 加密保存的邮箱恢复启用状态；明确暂停会保留暂停。旧版加密账号默认恢复。未保存的授权码仍仅驻留内存，不扫描其他邮箱客户端的凭据。
- 邮箱启动自动检查，之后每两分钟检查；首次建立基线不重播历史。通知关闭不阻止连接检查；通知开启时仅播报新增数量，不自动读取邮件正文。
- Codex 自动发现并复用本机登录，与 Harness Key、创建任务的目录解耦。断线指数退避重连，手动断开停止当前运行的重试；不自动发起收费推理。
- Codex 使用无 cwd 过滤、显式全来源、游标分页的只读任务发现，每轮检查最新页并推进旧页；保留所有已发现任务的跟踪。设置界面只显示最近 100 项，不限制监控范围。其他客户端的任务不接管审批和停止。
- 旧任务初次发现仅建立基线，不集中播报。已发现任务的新进展/结束进入实时信息及当前绑定范围的通知；只展示公开结果和摘要，不读取隐藏推理。
- WorkBuddy 继续自动扫描全部项目；不再因界面条数限制而丢弃其他会话的读取位置。单次日志读取最多 1 MiB，显示最近 100 项；CLI 发现补充系统安装目录和 macOS 应用目录。

## 绑定修复（三端源码）

Java 后端 `bind_success` 增加真实 `online` 与请求编号。保持已有增量广播，不在每次绑定时重新扫描账号全部设备。

手机消费权威在线状态；等待绑定时每三秒最多四次只读查询，以服务端列表核对结果，不重新提交绑定。
查询确认已绑定后同样执行成功收尾。回到前台检查连接新鲜度，心跳检测半开连接并重连；单个订阅者异常不再阻断其他页面。
退出账号、切换账号及取消/离开绑定页会清理等待，不将旧账号绑定操作发送给新账号。

手机/后端修改不包含部署或 APK 发布；只更新电脑 EXE 不能替代另两端更新。

## Windows 分发

- 安装器版本信息、应用 EXE 元数据与已安装应用 Publisher：`Ieasysell Limited`。
- 从已有品牌 PNG 机械生成 16/20/24/32/40/48/64/192/256 多尺寸 ICO。窗口/托盘使用 PNG，任务栏重启图标使用安装 EXE 内的图标资源。
- 保留原有设备身份、安装标记与 AppUserModelID，不清理用户配置、不修改系统 ACL、不关闭沙箱。
- Publisher 元数据不等于数字签名；测试版仍是未签名安装器。
