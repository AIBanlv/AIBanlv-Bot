# Harness 扩展评估

评估时间：2026-11-07。当前内置 Harness 依赖固定在 `0.2.1-rc.5`，执行组合由 `device-assistant-runtime.mjs` 控制，不自动加载用户全局插件。

## 结论

暂不默认集成 Subagent 和 Schedule；它们不是提高简单电脑指令识别率的前提。先修复现有语义路由与事件同步，再按复杂任务和本地离线提醒的实际需求提供可选能力。

| 扩展 | 当前已有能力与差异 | 默认策略 |
| --- | --- | --- |
| Subagent | 已通过 Harness 调度 Codex / WorkBuddy。上游的通用子智能体需要服务、提供方与模型工具组合，不能只装一个包。并行模型调用会增加额度、任务归属、取消和权限继承管理成本。 | 不默认加载。若引入，先限制深度、并发、总轮数及费用，确保子任务继承原授权并汇入真实进度；不得借子任务扩大工具范围。 |
| Schedule | 已有 `control_reminder` 和与手机共享的服务端定时提醒。上游 Schedule 需要持久化、会话恢复和宿主交付；只在短时任务子进程挂一个插件，不能保证退出或重启后可靠执行。 | 线上提醒继续使用现有链路，避免双重触发与绕过积分规则。未来本地定时模式需单独实现常驻调度、时区/去重、暂停/删除、到期费用和失效授权检查，再选择是否采用上游插件。 |

## 本次问题与修复范围

文字聊天与数字人共用 `DeviceConversation` 和 Harness 路由，没有另造一套“只会回复”的电脑助手。设置页收不到主进程实时事件，导致文字记录延迟；内部语义路由提示包含最近对话后超过执行通道的 2,000 字上限，导致 `INVALID_TASK`，并未调用实际电脑工具。

修复仅将只读路由的内部传输上限调整为 16,000 字，并在 JSON 转义后裁掉最旧上下文；普通执行任务仍限制 2,000 字，路由不能执行工具，取消、归属、文件和系统路径保护不变。明确磁盘操作使用 `control_open_folder` 的绝对根目录，例如 `D:/`，不使用任意 shell。

参考：[上游 Subagent 组合](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/subagent/subagent/README.md)、[上游 Schedule 宿主交付](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/schedule.md)。上游持续迭代，接入时需针对实际固定版本重新验证，不能直接假定当前文档等同于本项目已安装 API。

## 本地验证记录

- 真实内置 Harness + 本地模型夹具：长历史的语义分类、文字任务到目录工具执行通过；系统打开动作被替换，没有打开用户真实磁盘，也没有调用付费模型。
- Node 定向验证覆盖默认任务限额、转义后的路由限额、取消、消息分发、无音频缓冲进入设置页、角色上下文、README 文档链接，均通过。
- `node tests/device-settings-browser.mjs --local-roles-only` 与 `--conversation-access-only` 通过：流式原位更新、历史加载期间消息不被覆盖、账号/角色隔离、积分输入限制与恢复。聊天区域的桌面及窄屏截图已检查。
- 根目录 `npm test`：868 项，860 通过，8 失败；失败位置与修改前记录相同，涉及宿主原生进程/权限、受限子进程、PowerShell 与临时路径等环境问题，未在本次修改中调整。
- 真实 Electron 双窗口夹具已补充实时同步与重新打开历史断言，但启动被本机运行时目录的 Windows AppContainer ACL 拦截；隔离副本也未解决，不能宣称此项通过。未关闭沙箱、未改原依赖权限。完整设置浏览器套件另有已有菜单数断言不匹配（实际 7 个、断言 6 个），本次仅上述两个相关分支通过。
