# 桌面优化与积分规则（2026-10-25）

主仓库为 `control-windows`，Windows x64、macOS x64/arm64 共用界面。

## 功能

- Windows LAM 保留原 TAR/FP32 模型：CUDA 可用时，用三组波形比较输出误差与本机耗时。
  输出通过校验且至少快 5% 才自动选 CUDA；不可用或运行失败时回退 CPU。
  GPU 不支持 CUDA、或所用 PyTorch 未包含 CUDA 时走 CPU；WebGL 渲染仍独立使用图形加速。
  渲染按系统内存、CPU 核数与图形设备分低/均衡/高清，基础像素比分别为 0.75/1/1.5。
- 已绑定设备显示解除绑定；角色选择处提示通过手机定制私有角色。
- 分享保持手机邀请码和奖励文案，落地页改为 `https://aibanlv.ai/zh?view=desktop-companion`。
- 定时任务复用手机服务，支持单次/每日、时区、列表翻页和删除；电脑关闭后服务端仍执行。
- 左下角语言支持简体中文、繁体中文、英语、日语。用户内容保持原文。
- 对话按手机的 `[perform:...]` / `[msg_end]` 边界分段，不提前显示未完成片段。
- WorkBuddy/Codex 工作空间及任务发布入口已移除。Harness 负责选择已知空间、规划、审核和汇报；
  连接、进度监控和停止任务仍可在插件页使用。外部 WorkBuddy 文件监控保持原有协议。
- 任务完成后同步同账号手机消息与离线推送。结果先进入系统加密的待发送队列，最多 64 条、保留 7 天；
  账号变化不向新账号发送旧结果。推送失败/未注册设备时保留重试；服务端事件 ID 防重复入库。
  Harness 汇报失败时保留执行器真实结果。服务端“接收推送”不代表手机已展示通知。

## 积分

新注册 AI 伴侣使用 `9849c1b9-9c94-49de-9f65-9b802a1a3f8d`（AI伴侣默认套餐）。
邮箱注册在 CRM 创建后、返回令牌前，事务调整默认订单、初始积分流水和产品来源。
Google/Apple 客户端传 `mailBrand=aibanlv`；微信使用 AI 伴侣专属应用身份注册路径。
普通独立站注册继续使用原默认套餐。只改新注册，登录不会把旧账号强制改套餐。

首次认领将手机、电脑各自剩余的游客积分加入租户现有余额。例如原余额 800、手机余 500、电脑余 600，合并后 1900。
每租户手机/电脑各限首次一份；同一设备全局只可赠送一次，重复扫码、换绑和重连不能重复加分。
使用持久设备行和租户余额行锁，积分及流水同一事务提交。旧游客会话晚到结算从原接收租户扣除。
已按旧规则认领的设备不补赠，避免重新登录产生追溯奖励。

月度补足需要同时满足“AI 伴侣自助注册的服务端流水来源”和“当前有效的 AI 伴侣免费默认套餐”。
游客、有效付费订阅、其他产品、手动租户均排除。仅换成同名/同 ID 套餐不能获得资格。
按 Asia/Shanghai 自然月，每租户最多一次；余额低于 800 补至 800，达到或超过 800 保持不变。
当前由已绑定桌面上线及每 30 秒检查触发；并非每月第一天批量扫库清零。
旧租户来源不明时不自动纳入，需先用明确的产品注册名单迁移，不能按旧默认套餐批量授予资格。

## 发布与验证

必须同步发布 `live-broadcast-java` 服务端改动，再使用新版桌面及包含品牌字段的移动端。
发布前执行后端 `db/aibanlv-credit-indexes.sql` 添加领取键索引；该脚本不调整任何余额或租户资格。
旧服务端不支持新桌面接口时明确提示更新服务端。套餐 ID 必须已启用并配置初始积分与有效天数。
离线提醒依赖手机已注册推送 CID、系统通知许可及服务端推送配置，并遵循账号通知偏好。
没有部署服务、创建付费模型任务或构建安装包。

源码开发需要 Node 24+（Harness 使用原生 Zstd），安装后的 Electron 自带 Node。
本机完整 Node 回归 501 通过、14 个 Windows 专属跳过，覆盖汇报队列、换账号、规划审核。
服务端积分、套餐、扫码、任务提醒及推送专项 67 项通过；移动端 OAuth/积分页回归通过。
Electron 本地夹具验证四语言、HMAC 绑定、月度请求、任务增删、邀请、解绑及 320/650/960 宽度。
本机没有 NVIDIA GPU，CUDA 硬件与 Windows 打包内核需在 Windows 真机补验。
