## 跨网失败定位（2026-10-27）

本机最新日志确认：已获取 host/srflx 地址、发出 offer、收到手机 answer，随后 ICE failed，
DataChannel 未建立；这不是已送达或单纯未收集候选地址。用户确认手机使用流量/不同网络。
可判断跨网直连检查失败，不能仅凭日志断言具体 NAT 类型或哪一端防火墙限制。
另一轮手机立即 cancel，尚无手机日志佐证其原因，不能武断归因为用户手动取消。

当前仍为 STUN + ICE + DataChannel 纯直连：服务器只做授权和信令，不转发文件字节。
不同网络允许打洞直连，但运营商 NAT/防火墙可能使其不可行；增加 STUN 不等于保证成功。
仅在直连失败时启用 TURN/短时中转能提高可达性，但需要额外授权与服务配置并产生带宽成本；
本轮尚未获得增加中转的明确同意，因此未实现或启用任何隐式中转。

## 2026-10-27 连续发送失败定位

实际电脑日志（UTC+8）08:30:19 启动发送，08:30:28 报“直连候选收集失败”；08:38:07 启动，
08:38:15 同样失败，两次截图均约 720 KiB，均未记录 `transfer.offered`。
因此失败发生在电脑收集 ICE 地址、发出 offer 之前，不是图片未生成、文件超过上限或手机已收到。
本次独立 STUN UDP 探测 Cloudflare 219ms、Google 91ms 返回成功，只代表探测时当前路径可用，
不能据此判断历史时刻、所有网卡或真实手机网络畅通。

- 旧实现必须在 8 秒内进入 gathering complete，否则连已获得的地址也丢弃。新实现优先使用
  稳定的公网候选，收集期限到达时允许已有本地候选继续连接；没有地址仍明确失败。
- 两端显式同步 `device-direct-peer.mjs` / `utils/directPeer.mjs` 快照。
  使用 [Cloudflare 公共 STUN](https://developers.cloudflare.com/realtime/turn/) 与
  [WebRTC 官方示例中的 Google STUN](https://webrtc.github.io/samples/src/content/peerconnection/trickle-ice/)，
  只做地址发现，仍不启用 TURN、上传回退或文件中转。不能保证对称 NAT/受限运营商跨网直连。
- 手机失败后旧 currentId 未清空，后续 offer 被当作忙碌直接拒绝。新增失败用例先复现，再修复
  清空占用、通知电脑取消、保持接收页有效，可接下一份文件，无需退出重进。
- 取消显式文件/截图发送失败后的额外截图回执，避免自动再次拍摄并重复发送。
  Harness persona 与工具说明统一使用 request / latest_capture，不再默认引导旧 choose 选择器。
- 新日志记录 gather-ready、部分候选、公网/本地候选数量、offer、answer、channel-open、完整回执，
  不记录 SDP 或候选 IP。界面区分无直连地址、手机无应答、两端无法直连、手机取消与校验超时。

本地真实 WebRTC 夹具覆盖“地址存在但 gathering 一直未完成”仍传输成功，损坏文件仍被拒绝。
手机失败后连续接收已用组件逻辑夹具验证；没有发送用户私人图片/文件或启动收费会话。
真实手机跨网仍需新两端源码版本联调，未把本地夹具描述为真机已修复。

## 2026-10-27 修订（优先于历史选择器/逐份确认规则）

- 桌面 `send_file target=request` 从用户原始指令解析明确文件名，只查桌面、文档、下载目录的
  顶层受支持文档/图片/媒体文件，最多 8 MiB；不跟随文件符号链接、不选择凭据/程序。
  同名、缺少文件名、找不到文件时在对话中说明，不弹选择器、不自动选最近私人文件。
  手动 `choose` 仅保留给用户明确要求本机挑选的兼容路径。
- 手机已登录、当前设备绑定、前台接收页面和安全票据检查不变；符合校验的普通文件/截图
  自动接收，不再逐份弹确认。保存到本机仍是单独动作，不执行收到的文件。
- “发送截图”“截图发给我”也能直接路由；“发送刚才的截图”只使用最近截图。
  文件已收到完整校验回执时不再追加另一张任务截图，防止覆盖手机单文件接收槽。
  通过模型工具调度时保留原手机会话和原始文件指令，不能被模型改写扩大文件选择范围。
- 扫码聚合链接为 `https://aibanlv.ai/?deviceCode=编码后的设备码#bindToken=临时凭据&expireAt=过期时间`。
  外部扫码器打开官网；App 解析链接并通过原登录/绑定协议发起绑定，兼容旧 JSON 和手填设备码。
  临时凭据放 fragment，不进入官网 HTTP 查询或 Referer，不记录扫码原文；不降低后端绑定校验。

只修改桌面和手机源码，没有部署、构建安装包或发送私人文件。真实手机/跨 NAT 与微信扫码
仍需更新对应客户端后验收；本地夹具通过不表示真实网络端到端已成功。

## 后续修订（2026-10-26，优先于下文初评）

用户已授权修复桌面端并默认安装指定插件。本次不修改、部署后端或手机端，不构建安装包。

- 文件等待已定位到电脑选择器尚未选择文件，未发出 offer，不能当成手机已收到文件。
  桌面明确提示等待本机选文件，30 秒结束等待，取消立即收敛；迟到的选中结果不能发送。
  原生选择器不支持 AbortSignal，超时后若仍打开，需用户关闭；不累积多个选择窗口。
  “发送刚才的截图”只复用当前绑定的最近截图，不打开文件选择器或重新拍摄。
  发送组件 10 秒无响应、直连 40 秒未完成分别明确失败，避免先撞上 Harness 的 90 秒任务超时。
  选择、offer、发送进度和最终回执有独立状态；仍不启用 TURN/中转，不重发未确认的文件。
- 固定 npm `dsh-computer-use-mode@0.1.1`（MIT，lockfile 含完整性），Windows 默认内置。
  仅挂载工具入口，不加载其 bundle 中的 shell、文件系统、安装或委派工具。
  配套固定 `fflate@0.8.2`、`koffi@3.1.1`、`sharp@0.35.5` 与官方附件服务 rc.2，离线分发保留许可证。
  官方模型目录的 deepseek-flash 明确声明 text/image；真实账号的模型能力仍以实际服务为准。
  GUI 工具经现有 ACP callId/session 和私有 broker 授权；审核器、汇报器、未授权手机不能绕过门禁。
  屏幕观察默认可用；输入每步本机确认，批量仅允许最多四次观察，不执行批量盲点。
  限定输入长度和等待时间，阻止命令行、安全窗口和 Windows 快捷入口，停止后不能开始新步骤。
  系统已经接收的输入不能保证撤销，不自动重试结果不确定的输入。
  0.1.1 首次截图的 undefined 字段在适配出口转为无损 JSON，图片引用保留在输出中。
  图像附件在隔离 Harness 会话目录内，随会话清理；观察图像会共享给配置的模型并可能增加费用。
  Mac 不加载 Windows GUI 插件，原有受限工具继续工作。

本地模型夹具已验证真实 Harness 握手及两个新工具注册，附件服务使用合成 PNG 验证；
没有实际点击用户应用、发送私人文件或创建收费模型请求。Windows 目录 ACL 仍阻止原生
Electron 窗口夹具，不能据此宣称真实电脑操作或手机端到端已验收。

## 本次落地范围

桌面、后端和手机源码一起更新；不部署、不打 EXE/APK、不替用户发送私人文件或邮件。
邮箱仍是只读能力，发送邮件会明确说明尚未接入，不允许用“已发送”替代真实结果。

- 高频明确操作指令（如“打开微信”“电脑截个图发到手机”）先由应用统一调度 Harness，
  不再依赖语音模型恰好选择工具。疑问、否定、引用和普通聊天不强制执行。
- 原生主屏截图；文件只能来自本机选择器或当前绑定下最近截图，不接受模型提供任意路径。
- WebRTC DataChannel 直传，单文件 1 字节至 8 MiB，16 KiB 分片，SHA-256 校验后回执。
  STUN 仅用于发现地址；无 TURN、服务器文件中转、对象存储或上传回退。
  低成本不是完全无流量：后端仍承担少量 HTTPS 授权、WebSocket 信令；两端承担文件流量。
- 手机“设备 → 接收电脑文件”可接收普通文件并手动保存；远程对话页挂载同一接收组件，
  前台自动接收执行截图。普通文件仍逐份确认，不自动执行收到的文件。
- 新后端为每条远程消息覆盖写入真实 `originSessionId`。截图回执只投递该已授权会话，
  原手机离线或未开启接收不回退发给同账号其他设备。
- 每条远程操作在执行调用返回后截图；失败也可返回现场。创建 Codex/WorkBuddy 后台任务时
  这只是“提交时现场”，不是该后台任务最终完成的证明。后台公开进度仍由原任务监控汇报。
  截图结果与任务执行结果分开，截图成功不能把失败任务改成成功。
- 自动回执只保留内存中的最近截图，避免每条远程命令积累本地图片；显式“截图”才保存本机。
  自动回执最多等待 20 秒；文件传输有独立超时，取消/断网/解绑清空传输内存。

## 账户和新能力授权

旧控制 WebSocket 身份由注册字段提供，不能单靠这些字段开放姓名、积分和文件能力。
新增能力不扩大旧协议权限：

1. 电脑使用原扫码配对 secret 和服务端会话 nonce 做 HMAC；secret 仅主进程使用、系统加密保存，
   不进入模型、renderer、日志或仓库。服务端从有效设备绑定推导账号，只返回名称和积分。
2. 手机用已有 JWT 请求 `/client/control/transfer-ticket`，票据绑定账号、租户、设备与当前
   WebSocket session，5 分钟过期，仅内存保存，断开即失效，不进入 renderjs。
   同一票据用于远程 `send_text` 的工具授权，服务端验证后覆盖 `computerAuthorized` 并剥离票据；
   新桌面拒绝未通过手机登录授权的操作命令，旧客户端普通聊天/历史仍兼容。
3. 信令严格限制字段/长度/文件大小并限流；服务端不接受 base64、分片或任意文件字段，
   转发前剥离票据、电脑证明和路由目标。

旧电脑绑定如果没有安全凭据，需要在手机解绑后重新扫码一次；不做不安全的自动授权降级。
必须三端源码上线对应版本后才能真实联通。本次未改数据库结构。
账号菜单“退出登录”仍按用户要求关闭软件，不主动解绑。

## 插件初评：有价值，但不直接默认安装

候选是 [EvangeliMo/dsh-computer-use-mode](https://github.com/EvangeliMo/dsh-computer-use-mode)，
不是同名近似的其他插件。已阅读上游 README、package.json 和 loader；包自报版本 0.1.2、MIT。
它提供鼠标键盘/窗口及视觉截图工具，适合没有 API 的 GUI 软件；并非本次截图和文件直传的前置依赖。
它依赖完整 Harness 宿主布局提供 koffi/fflate 等包，截图观察要求模型具备图像输入能力。
视觉分析会增加模型图像输入和多轮推理的费用，不应与不经服务器的截图直传成本混为一谈。
本项目是固定版本、限工具的内嵌 Harness worker：安装候选包本身不会自动补齐宿主、附件、
工具权限、原生模块打包和视觉模型配置，需要独立适配。当前 DeepSeek 对话配置不能直接视为可看图。

建议后续作为“受控电脑操作”可选能力随安装包离线内置；不要在本轮直接改生产依赖或运行安装脚本。
启用前要锁定版本/commit 和完整性、保留 MIT 声明，逐文件审计原生调用、依赖来源及权限，
验证多屏/DPI/中文输入/窗口切换/停止/敏感操作确认和失败回滚，再做真实 Windows 验收。

“自我提升”优先做可审查的任务经验/技能草稿，不默认给远程会话任意改代码、改安全策略或
联网安装插件的权限。[官方 extensions 说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/extensions/README.md)
提供扩展机制，但不等于可安全默认开放自主升级。具体自我提升插件尚未指定，不能凭名称完成安全审计。
