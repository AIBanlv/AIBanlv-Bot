# 邮箱注册实施计划

用户明确的范围为单一邮箱注册能力，复用现有登录绑定，不改变服务端。

依赖顺序：有界注册请求 -> 单任务注册/登录/绑定 -> 表单与 IPC -> 本地验收。

1. 先验证输入与注册接口契约，加入主进程请求和本地失败测试。
2. 复用 DeviceLogin 的取消、超时、重入及服务端确认；保留注册已成功结果。
3. 增加注册/登录切换、验证码重发、状态、焦点与窄 IPC；
   更新模块服务/打包清单但不构建包。
4. 扩展现有 Electron 夹具，验证错误、取消、键盘、布局、axe、凭据隔离、
   默认形象及原扫码登录回归；记录精确结果。

风险：注册 GET URL 含密码，不能返回或记录 URL；服务端可能已经创建账号
但尚未返回成功，取消不提供事务回滚；内部登录失败提示只能识别已核实
固定文案，不能把任意错误文案当作成功。后续绑定必须仍通过 DeviceChannel。

检查点：每个代码切片运行 focused tests，最终运行根目录完整 Node suite
和 Electron 本地夹具。保留用户现有未跟踪 IDE 文件，不修改其他仓库。
