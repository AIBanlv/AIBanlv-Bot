# 桌面端仅扫码授权（历史规格）

2026-11-02 补充：“必须扫码才能使用桌面”的部分已由[独立运行说明](standalone-desktop-guide.md)替代。
账号密码登录仍移除，扫码仍是唯一账号登录方式；游客现在可使用本地形象和自有 Key。
下方保留此前版本的实施与验证记录。

2026-11-02：用户要求删除账号登录，桌面只允许扫码进入。本规格取代桌面账号登录、
邮箱注册及未绑定游客对话的入口约定；服务端其他客户端账号接口不变。

## 目标与迁移

- 设置页只展示设备绑定二维码、到期状态和刷新连接；删除账号、密码、注册和验证码表单。
- 删除主进程账号登录/注册请求、临时 controller 连接、对应 preload 方法和 IPC handler。
- 未绑定、身份未确认及断线时，禁止角色加载、目录查询、业务 HTTP、文字/语音对话和麦克风。
  即使旧状态包含 `guest: true`，也不能恢复游客权限。解绑立即清理角色和对话，显示扫码入口。
- 仅接受现有可信控制连接确认的绑定，不把本地状态或输入账号当作授权。
  已有有效扫码绑定重启后可恢复；协议不能区分历史扫码和历史账号授权的服务端绑定，
  因此不批量解绑已有设备。旧账号登录请求和自动注册授权不再执行。
- 保留绑定后的角色、设备证明换 JWT、积分、零积分纯文字模式和其他插件功能。
- 保留历史游客记忆的加密读取及绑定后的原归属补传，防止升级丢失旧记录；不能据此授予权限。
- 不删除用户本机配置，不修改服务端/legacy，不新增依赖，不构建或部署安装包。

## 实现与顺序

所属项目 `demos/web-desktop-pet`，ES modules、Electron、Node 24 内置测试。
沿用单引号、camelCase、小函数、既有二维码布局及具名 IPC，不引入新的登录页或状态框架。

1. 先为扫码唯一入口、旧 guest 状态拒绝、模块分发写失败测试。
2. 移除登录与注册 UI/IPC/网络模块，更新打包和本地资源白名单。
3. 收紧主进程、角色目录/加载、HTTP 和输入的授权条件，保留绑定恢复和旧记录迁移。
4. 用新的拒绝/扫码测试替换被删除功能的测试，更新本地 Electron 和设置页浏览器夹具。
5. 运行全量 Node 与实际 Electron 验收，检查屏幕宽度、键盘、axe、控制台及零生产请求。

## 成功标准

设置页与两个 renderer bridge 都无账号登录/注册接口；产物不含旧网络模块。
未绑定与旧 guest 状态的输入、目录、资源下载、业务 HTTP 为零；二维码可正常读取、刷新，
手机扫码确认后可换 JWT 并调用四类受保护接口；断线和解绑重新关闭权限，重连恢复真实绑定。
保留敏感状态隔离、租户切换清理、无积分已绑定文字模式和历史记忆补传测试。
测试不调用真实账户或付费服务；生成产物与本机文件不提交。
